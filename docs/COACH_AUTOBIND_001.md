# COACH-AUTOBIND-001 · Chrome v0.3.8 candidate

The Chrome extension can request the active Sidecar pairing over Chrome Native Messaging. The host is registered for the single fixed extension ID `bapcebjlgncogfpgbhllioaichcldkbl`; it reads only `coach-current-pairing.json` in DevSpace's owner-only state directory. The Sidecar atomically replaces this mode-0600 file after a successful explicit start and removes it on stop. It is never served over unauthenticated localhost HTTP, exposed to page scripts, or printed by the native host. If the host is missing, Chrome denies it, or its handoff is unsafe, manual pairing remains available.

One-time setup (only after release approval): run `node scripts/install-coach-native-host.mjs [DevSpace-stateDir]` on macOS and approve the Native Messaging/extension permission; restart Chrome to load the registration. This registers a native host only and does not install the extension or start the Sidecar. The default state directory is `~/.local/share/devspace`; pass the configured `DEVSPACE_STATE_DIR` when customized. The installer copies the audited host to stable, owner-only `~/Library/Application Support/DevSpace/CoachNativeHost/host.mjs` (mode 0600), and writes a tightly allowlisted Chrome host manifest/launcher with mode 0600/0700 in the user's NativeMessagingHosts directory. It rejects symlinked or foreign-owned targets, so cleanup of a Git worktree cannot silently break the host.

Route consent lives in `chrome.storage.local` under exact `workspaceId` keys. Each workspace needs an explicit chat bind and explicit enable action. Incoming events must carry a valid trusted `workspace_id`; a matching route is required before any send. On browser startup and each delivery poll, the extension matches each saved canonical conversation URL against open tabs and only accepts one exact match. Missing or duplicate matches stop delivery while retaining the approved URL and enabled grant. Events with no usable workspace ID remain in the identity ledger as unidentified pending work and are never routed. An event without a route cannot block another authorized workspace. Token rotation does not create or enable a route. Send outcomes that become uncertain remain in the existing durable event ledger as `needs_attention` and are never retried automatically. Ledgers store event identities and statuses, never pairing tokens.

After the user explicitly selects **From this device**, the extension may remember a boolean Native Messaging consent and request the current handoff at browser startup or on its existing one-minute pairing poll when the session pairing is missing or stale. The bearer remains only in `chrome.storage.session`. If the native host is unavailable, manual pairing remains available. **Clear pairing** removes that consent, all saved chat routes, and the session bearer.

For a fresh installation, starting Sidecar and authorizing exact workspace IDs remains an explicit action. COACH-AUTOBIND-002 adds automatic recovery **only for previously persisted, explicitly authorized Sidecar configurations** in both Worker and non-Worker modes; explicit stop/revocation prevents restart.

## COACH-AUTOBIND-002 · Authorized multi-worktree Sidecar and restart closure

- Reused existing Codex Worker owner-only persisted Sidecar configuration/auto-recovery instead of introducing a second overlapping Worker scheduler.
- Added a durable, bounded **explicit** `authorizedWorkspaceIds` consent list (1–8, must include the primary workspace), validated independently by both MCP WorkspaceRegistry and the Worker persisted-session/allowed-root checks, including on restart. No implicit discovery of all worktrees.
- A single localhost `/events` request now returns the verified union of **only** authorized workspaces (up to 50 pending); optional `?workspaceId=...` supports a narrower exact lookup and rejects unauthorized queries. Responses retain each source workspace ID; event IDs and delivery receipts remain identity-scoped. More than 50 pending events still intentionally fail closed in Chrome; paging is a separate enhancement.
- Native non-Worker API startup now resumes previously explicit persisted Sidecar consent, validates workspace roots, rotates ephemeral pairing token, retries failed starts safely, and honors explicit stop/revocation; Worker mode retains its existing fenced restoration and protected stable bearer mechanism.
- Verified in the isolated worktree with locked `npm ci`: TypeScript `npm run typecheck` **PASS**; native SQLite Sidecar MCP integration **PASS**; real Codex Worker lifecycle + restart/port collision recovery **PASS**; non-Worker `createServer → close → createServer` restoration and explicit stop **PASS**; full `test:coach:mac` **PASS**; `test:coach:observer` **64/64 PASS** after updating prior single-workspace-only source-text assertions.
- Security negative cases: unauthorized workspace selector, duplicate selector, legacy single-workspace denial, identity-scoped browser receipts, invalid persisted scope, wrong workspace, and stale route resurrection. Initial isolated tests were re-run after fixture and expected 400-response updates.
- These tests prove controlled local process recovery, **not** Chrome Browser UI permissions, real Native Messaging installation, or Web GPT's behavior when the browser is closed. The production DevSpace daemon/Chrome extension remain unchanged.
