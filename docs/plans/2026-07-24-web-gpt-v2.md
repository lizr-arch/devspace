# DevSpaceMac v2 plan for Web GPT

Implementation status: phases 1 through 4 are implemented, tested, and deployed
on the DevSpaceMac service. Later capabilities remain separately gated.

## Goal

Give Web GPT enough explicit, inspectable tools to resume approved local work,
run long validations, import generated assets, and report trustworthy evidence
without broadening filesystem access or turning DevSpace into an autonomous
local agent.

## Phase 1: operational visibility

- Add `devspace_info`.
- Report the running package version, boot ID, uptime, schema revision and
  fingerprint, enabled tool names, mode flags, approved roots, and task limits.
- Keep `/healthz` lightweight while making MCP-side diagnostics detailed enough
  to distinguish a stale ChatGPT tool snapshot from an old local process.

Acceptance:

- A client can compare `bootId`, `schemaRevision`, `schemaFingerprint`, and
  `tools` before and after a restart or ChatGPT action refresh.
- No OAuth secret, tunnel credential, environment dump, or file content is
  returned.

## Phase 2: persistent workspace discovery and recovery

- Add `list_workspaces` over persisted workspace sessions.
- Add `resume_workspace` so a managed worktree can be restored by
  `workspaceId`, even though its generated path is intentionally outside the
  normal `allowedRoots`.
- Re-run path policy checks, directory existence checks, AGENTS discovery,
  skills discovery, and optional Project Memory preflight during resume.

Acceptance:

- A server restart does not force Web GPT to remember an inaccessible managed
  worktree path.
- Sessions whose source roots are no longer approved are not disclosed.
- Missing worktrees are reported as non-resumable and are never recreated
  implicitly.

## Phase 3: controlled background validation jobs

- Add `start_job`, `poll_job`, and `cancel_job`.
- Accept a named validation runner plus an argument array, never an arbitrary
  shell command string.
- Allow only build/test/check runners such as npm, dotnet, Godot, Cargo, and
  pytest, with per-runner argument policy.
- Resolve the executable independently, spawn without a shell, constrain the
  working directory to the workspace, cap runtime/output/concurrency, persist
  metadata and logs, and support cancellation.

Acceptance:

- A long validation survives an MCP request timeout and can be polled.
- Shell metacharacters are inert arguments, not executable syntax.
- Jobs cannot select an arbitrary executable or working directory.
- Logs are bounded and credentials/environment variables are not returned.
- Server shutdown terminates live child processes.

## Phase 4: dedicated inspection tools and deployment

- Run DevSpaceMac with full tool mode so Web GPT receives `grep`, `glob`, and
  `ls` instead of emulating all inspection through `bash`.
- Keep `bash` for foreground commands and keep its existing no-file-write
  contract.
- Preserve the single approved source root `/Users/liz/threecountries`;
  managed worktrees remain reachable only through their persisted workspace
  IDs.

Acceptance:

- Local and public MCP discovery report the same tool list and fingerprint.
- OAuth initialization, tool discovery, workspace resume, a real background
  validation, polling, and cancellation all pass through the public endpoint.

## Later gated capabilities

These are intentionally separate releases because they add stronger mutation
or human-authority semantics:

- Generic `import_asset` after MIME, size, provenance, and destination policies
  are specified per asset family.
- `preview_artifact` and `export_artifact` for reviewable images/audio/reports.
- `git_checkpoint` for local, path-scoped commits.
- `git_publish` only with an explicit user gate and branch/remote confirmation.
- `run_validation_profile` for repository-owned named validation suites.
- `review_queue` and `evidence_bundle` that record, but never synthesize, human
  visual/audio/play-feel approvals.

No phase may auto-merge, auto-push, approve a human gate, expose `/Users/liz`,
or provide a hidden autonomous coding loop.
